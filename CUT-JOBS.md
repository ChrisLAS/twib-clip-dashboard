# Disabled inventory cut requests

This isolated slice persists structured owner cut requests alongside existing inventory reviews. It does not activate execution. Syncthing remains the authoritative media location; the dashboard stores request/provenance metadata and plays explicitly selected workstation files.

## Request behavior

Choose **Explicit range** or **Editorial guidance**, then save **Cut down** once. Positive explicit ranges must be at most 180 seconds with millisecond precision. Preserve complete thoughts and qualifications. A start-only or theme request remains editorial `needs_review`; the client never parses old free-text notes into executable cuts.

A missing or unknown `CAPTURE_JOBS_GRANT_OPERATIONS` is closed. `cut` authorizes cut execution only; `capture` authorizes URL capture only; `capture,cut` explicitly authorizes both. The server checks this boundary for owner capture routes, default/explicit machine claims and results resolved by immutable stored job kind, before any replay. Claim expiry cleanup and lease lookup are also restricted by kind. Request-only persistence does not require machine execution authority.

A request binds the existing item/native IDs, observed source version/hash, review revision and decision. Persistence and the review operation commit together. An unchanged uncertain save retains its operation UUID with the draft, including across pagination/filter unmounts. Current-source/current-review/unique-native-identity guards apply inside initial queue and explicit retry transactions. Generic capture retry cannot bypass them.

## Nomad execution and review boundary

`cut_worker.py` resolves exactly one existing local_files/downloaded native identity and requires its current path to equal the episode-relative source. Missing IDs/hashes, duplicate identities, changed source, symlinks, stale episode binding and invalid boundaries refuse execution. No filename guessing creates identities. Only range requests execute.

The existing show lock serializes supported native history writers. Input is pinned, copied into private staging, hashed and checked for change. ffmpeg execution, generated bytes, output duration and full decode are bounded. Publication uses exclusive creation in `new-review/<request UUID>-a<attempt>.mp4` and a receipt; it never overwrites a destination. The child is appended to native `local_files` with immediate parent, source ancestor, source/output hashes and local range. Parent history is preserved; approval is explicitly `unreviewed`, readiness false. Original media, prep, manual layout, player order and set-aside state are not modified.

Partial publication/history failures park for operator reconciliation; no automatic replay, cleanup of published media or promotion occurs. Durable worker/poller journals replay matching claim/result receipts after lost replies. Accepted derivative attachment cannot be erased by stale or concurrent result deliveries and prevents another retry. Each explicit eligible retry uses a new bounded attempt filename.
